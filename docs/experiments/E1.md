# E1 edge-based Dijkstra throughput

The Germany measurement awaits the pinned Germany bundle and oracle in
[#239](https://github.com/zig-utils/zig-routing/issues/239) and a Linux host
with exposed hardware counters in [#14](https://github.com/zig-utils/zig-routing/issues/14).
The E1 decision requires at most 150 ns per settled label and at least 5x
the oracle's label throughput for the same expansions.

## Luxembourg pilot

The search kernel was at `4ec7924`, built in ReleaseFast with
`0.17.0-dev.1857+3c46da14d`. The pilot ran in an aarch64 Linux VM with six
virtual CPUs on an Apple M3 Pro. The native bundle used the Geofabrik
Luxembourg 2026-01-01 PBF, SHA-256
`d8f3e1dabb4d9d5489500c35432eb393089c32222cfff8cf50706852f0696a80`.
The bundle contains 187,650 nodes and 475,336 directed edges.

The experiment drew ten source nodes with seed 82 and warmed each source
once per kernel. The cap was one million labels per sweep. The reported
weighted mean divides total elapsed time by total settled labels.

| Kernel | Settled labels | Largest sweep | Weighted ns/label | Median ns/label |
| --- | ---: | ---: | ---: | ---: |
| Pedestrian | 4,584,670 | 458,467 | 173.731 | 166.102 |
| Stub motor | 2,333,384 | 291,673 | 198.297 | 167.328 |

Two stub motor sweeps settled zero labels. The median uses the nonempty
sweeps. Both pilot kernels exceeded 150 ns per label. The VM exposed
software event sources, and all hardware counter fields were null. The
5x comparison awaits the matched Germany run.

## Reproduction

```bash
zig build bench-search -Doptimize=ReleaseFast -- BUNDLE 10 1000000 82 > result.json
```

The report records the dataset UUID, architecture, seed, source IDs, settled
and popped labels, elapsed time and per-label hardware counters. The
pedestrian kernel uses the compiled default profile with an unbounded
distance budget for Dijkstra. The motor stub uses tagged access, base speed,
the turn restriction bit and stop impact.

The Germany run should use the same graph, source nodes, cost kernels and
one-million-label cap on both engines. If E1 misses either gate, profile
loads of the hot edge and label records alongside the queue and turn tables
before changing their sizes or layout.
